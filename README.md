# wechat-video-auto

微信 PC 版（4.x，Windows）自动化：**搜索关键词 → 打开搜一搜结果页 → 切到「视频」→「账号」→ 滚动到底，把全部账号导出成文本**。

```
微信主窗口搜索框输入「羽绒服库存」
      ↓ 点击下拉里的「搜一搜 / 搜索网络结果」（没有就按回车）
搜一搜结果页
      ↓ 点「视频」tab → 点「账号」
账号列表：边滚动边 OCR，跨屏去重，直到到底
      ↓
output/羽绒服库存_时间/accounts.txt   ← 每行一个账号名
                    accounts.csv   ← 序号 / 账号名 / 简介等详细信息（Excel 可直接打开）
                    accounts.json
```

## 快速开始

1. 安装 **Python 3.9 ~ 3.13（64 位）**，安装时勾选 *Add Python to PATH*。
2. 打开并**登录**微信 PC 版（最小化、缩到托盘都可以，脚本会自己唤起）。
3. 双击 **`run.bat`**，输入关键词回车。第一次运行会自动建虚拟环境并安装依赖（清华镜像，几分钟）。
4. 运行期间**不要动鼠标键盘**；**按住 F12** 可随时中止（已采集的数据会保留）。

命令行用法（在项目目录下）：

```bat
.venv\Scripts\python -m wxva 羽绒服库存
.venv\Scripts\python -m wxva 羽绒服库存 --max-accounts 300     :: 最多采 300 个
.venv\Scripts\python -m wxva 羽绒服库存 --scroll-wait 2         :: 网络慢，每次滚动多等一会
.venv\Scripts\python -m wxva 羽绒服库存 --debug                 :: 保存每一屏截图 + OCR 结果
.venv\Scripts\python -m wxva --probe                            :: 只测第 1 步：唤起微信主窗口
.venv\Scripts\python -m wxva 羽绒服库存 --start-from tabs       :: 搜一搜页已手动打开，从切 tab 开始
.venv\Scripts\python -m wxva 羽绒服库存 --start-from list       :: 已手动切到「账号」列表，只做滚动采集
```

### 批量关键词

双击 **`batch.bat`**：第一次会生成 `keywords.txt` 并用记事本打开，每行填一个关键词、保存，再双击一次即可。
也可以命令行：`.venv\Scripts\python -m wxva -f keywords.txt`。

输出在 `output/batch_时间/`：每个关键词一个子目录（同单个关键词的输出），外加
`汇总_全部关键词.csv`（关键词/序号/账号/详情）和 `汇总_去重账号名单.txt`（跨关键词去重）。
某个关键词失败不影响后面的；按住 F12 中止时已完成的部分照常汇总。

### 建议的首次使用顺序

1. **`selftest.bat`** —— 不碰微信，用记事本检查本机的「最小化窗口唤起到前台 / 剪贴板粘贴中文 / 截图 / OCR」
   是否正常。这一步不过，说明是电脑环境问题（锁屏、远程桌面、安全软件拦截模拟输入、权限）。
2. **`probe.bat`** —— 只做第一步：找到并唤起微信主窗口，截图保存到 `output/probe_时间/probe_main.png`。
3. **`run.bat`** —— 正式跑。

## 为什么「唤起微信窗口」这一步不会卡死

之前很多脚本死在第一步，常见原因和这里的做法：

| 常见死法 | 本项目做法 |
| --- | --- |
| 用 `uiautomation` / `pywinauto` 找微信窗口、`SetFocus`。微信 4.x 是 Qt 自绘界面，UIA 树基本是空的，深度查找/跨进程 UIA 调用经常无限等待 | **完全不用 UIA**。纯 `ctypes` 调 Win32：`EnumWindows` + 进程名（`Weixin.exe`/`WeChat.exe`）+ 类名（`Qt51514QWindowIcon`，只作加分项）+ 标题 + 尺寸打分定位 |
| `win32gui.SetForegroundWindow` 被系统拒绝时直接抛 `pywintypes.error`，脚本崩溃 | 前台切换**从不抛异常**，逐级降级：Alt 键解锁 → `AttachThreadInput` → 置顶/取消置顶 → 真实鼠标点击标题栏空白处 |
| 微信缩到托盘时 `IsWindowVisible()==0`，按"可见窗口"找不到；对隐藏的 Qt 窗口 `ShowWindow` 会显示成空白 | 不按可见性过滤；隐藏时**重新运行一次 `Weixin.exe`**（微信是单实例，只会激活已运行的微信并显示主窗口，和双击桌面图标一样），失败再发 `Ctrl+Alt+W`，最后才 `ShowWindowAsync` |
| `ShowWindow` / `SetWindowPos` 跨进程调用在目标忙时阻塞 | 只用 `ShowWindowAsync` 和 `SWP_ASYNCWINDOWPOS`，不会阻塞 |
| 高 DPI 屏幕上坐标对不上（点歪） | 启动时设置 Per-Monitor-V2 DPI 感知，窗口坐标、截图、鼠标统一为物理像素 |
| 真卡住时"没反应"，不知道卡在哪 | 看门狗：任何一步超过 180 秒没有进展，把 Python 堆栈写入 `watchdog_traceback.txt` 并退出 |

另外会检测：微信没运行、微信未登录（只有登录小窗口）、屏幕已锁定，都会直接给出明确提示，而不是傻等。

## 各步骤怎么定位按钮（不写死坐标）

所有「找按钮」都靠**截图 + 本地 OCR（RapidOCR，离线，模型已内置）**找文字位置，并使用逐字坐标——
即使 OCR 把一整排 tab 识别成一行 “全部文章公众号视频小程序”，也能精确算出「视频」两个字的位置去点击。

1. **搜索框**：OCR 找主窗口左上角的「搜索」占位文字 → 点击；找不到依次尝试两个默认位置、`Ctrl+F`。
   每种方式粘贴关键词后都会**截图确认搜索框里真的出现了关键词**，才进入下一步。
   （这个校验保证之后按回车时焦点一定在搜索框，不会误把文字发到聊天里。）
2. **搜一搜入口**：OCR 下拉框里的「搜一搜 / 搜索网络结果」并点击；没有这一项则按回车。
3. **结果页**：自动识别新弹出的窗口（或嵌在主窗口里的页面），以「同一行出现 视频 + 全部/文章/公众号…」判定为结果页；
   并且**等页面上出现本次的关键词**才继续——搜一搜窗口可能是上次留下的旧结果，不会误采旧数据。
4. **视频 → 账号**：按行打分找 tab（排除「视频号」、排除搜索框里的关键词），点完等待页面稳定。
5. **采集**：
   - 头像检测 + 文字列对齐 + 「名字行更黑/更大」三重特征把每屏切成一张张账号卡片；
   - 被上下边缘截断的卡片丢弃（滚动有重叠，下一屏会完整出现）；
   - 用两屏的文字匹配 + 像素匹配精确测量每次滚动了多少像素，**自动调整滚动幅度保证相邻两屏重叠约 45%**，
     万一滚过头（两屏无重叠）会自动回滚；
   - 去重同时依据「位置映射」和「名字+简介」，同一账号多次识别的名字做投票，抵消个别 OCR 误差；
   - 连续滚不动 / 出现「没有更多」/ 连续几屏没有新账号 → 判定到底；
   - 每新增账号就立即写盘，中途中止也不丢数据。

## 排查问题

每次运行的 `output/关键词_时间/` 下都有：

- `run.log` —— 详细日志（每一步做了什么、点了哪里）
- `debug/*.png` + `debug/*.json` —— 每个关键步骤的截图和 OCR 结果（加 `--debug` 还会保存每一屏）

常见情况：

- **微信以管理员身份运行**：Windows 不允许普通权限程序向管理员窗口发送输入，脚本也要以管理员身份运行（右键 `run.bat` → 以管理员身份运行）。
- **某一步没找到按钮**：看 debug 里对应截图；也可以手动做完前面的步骤，用 `--start-from tabs` 或 `--start-from list` 继续。
- **网络慢、列表加载不出来**：加 `--scroll-wait 2` 或更大。
- **锁屏 / 远程桌面最小化**：模拟输入无法送达，需要保持屏幕亮着、会话在前台。

## 项目结构

```
wxva/
  winapi.py        纯 ctypes Win32 封装（窗口定位/前台/输入/剪贴板），无 pywin32 依赖
  platform_win.py  Windows 平台：唤起主窗口、前台切换、截图、鼠标键盘
  ocr.py           RapidOCR 封装，输出行框 + 逐字框
  parser.py        一屏截图 → 账号卡片；跨屏去重收集器
  automator.py     主流程（搜索 → 结果页 → tab → 滚动采集）
  cli.py           命令行入口、输出文件、日志、看门狗
tests/
  sim.py           模拟的「微信 + 搜一搜页面」（真实字体渲染成像素，响应点击/滚轮/粘贴）
  test_flow_sim.py 在模拟页面上用真实 OCR 跑完整流程
  selftest.py      不依赖微信的环境自检（记事本）
run.bat / probe.bat / selftest.bat / batch.bat
```

## 测试

```bash
pip install -r requirements.txt pytest
python -m pytest tests -s
```

测试在模拟平台上用真实 OCR 跑完整流程，覆盖：100% / 150% 缩放、深色模式、下拉项文字不同、
搜索页嵌在主窗口里、单格滚动过大（需要回滚）、没有头像（按名字样式分组）、找不到「搜索」占位符
和下拉项时的降级路径、90 个账号分批懒加载、搜一搜窗口残留旧关键词结果、批量多关键词。所有场景要求**账号一个不漏、一个不多、顺序一致**。
（Linux 上需要中文字体，可用环境变量 `WXVA_TEST_FONT` 指定；Windows 上自动使用微软雅黑。）
